## Repetición

- Prerrequisitos: Docker y Compose disponibles; `.env` local con una contraseña de prueba; navegador con acceso a `http://localhost:8080/portfolio/`; acceso SSH a la VPS; contraseña de producción ya entregada fuera del repositorio; credencial SSH localizable con `Get-ChildItem -Recurse $env:LOCALAPPDATA -Filter personal-vps-ssh.clixml`.
- Para el subpath, exportar `VITE_BASE_PATH=/portfolio/` antes de `docker compose up -d --build`. El `.env` local define `/` y no debe usarse para esta prueba.
- Los comandos con `curl` y variables de shell se ejecutan en Bash/WSL o Git Bash; en PowerShell se adapta la expansión. Los archivos temporales de cookies y respuestas (`/tmp/...`) quedan fuera del repositorio y se eliminan al terminar.
- Orden recomendado: RF-03 (arranque) → RF-01/RF-02 (sesión, uniformidad y rechazo) → RF-04/RF-05 (CRUD e imágenes descartables) → RF-07 (seed) → RF-06 (público y producción) → RF-08 (integración y VPS).
- Para el seed, usar base local nueva o la prueba unitaria. No borrar `portfolio_postgres_data` ni `portfolio_project_media` en la VPS.
- Cada reintento debe registrar comando, entorno, resultado y evidencia resumida; si cambia el diagnóstico, anotar qué se corrigió y qué RF se volvió a probar. Nunca incluir la contraseña, el hash ni tokens reales en la evidencia.
